# 轻解 2.2：Bandizip 解压功能对标与实现记录

核验日期：2026-11-25。对标对象以 Bandizip **macOS 版**的官方功能和帮助文档为主。本文区分官方公开行为、开源工程资料、本次已实现内容和尚未解决的兼容性；没有获取或复制 Bandizip 的私有源代码。

## 1. 加密 RAR 5 错后缀样本的修复与验证

`st-12.zip` 的签名是 RAR 5，并有加密目录。外层容器识别成功，不等于内部压缩方法可以被当前解码器解码。

问题分为三个独立阶段：

1. **错误后缀**：按内容签名判断真实格式，不修改原文件。
2. **普通文件被误判为特殊条目**：旧代码根据字段名是否包含 Link / Stream 判断风险。RAR/7-Zip 的技术目录会为普通文件提供值为 `-`、空值或计数的属性；只有明确的属性值才可用于类型判定。现在检查已知字段的实际值和 POSIX 文件类型，并增加模拟元数据、真实 RAR 5 样本与恶意链接测试。
3. **Unsupported Method**。旧 p7zip 17.05 的格式列表含 Rar/Rar5，但解码器列表缺少 Rar1、Rar2、Rar3 和 Rar5。官方 macOS arm64 版 7-Zip 26.06 提供这些解码器。已在应用中用新版完成真实的 45.6 MB 样本解压，任务显示 1 个文件、0.63 秒。该耗时仅记录这次任务。

安装包已内置 26.06，保留用户单独更新引擎的入口。公开压缩 RAR 5 样本作为回归用例，检查解压字节数和 CRC-32。它与使用 Store 方法的另一个样本分别覆盖压缩和原样存储条目。

## 2. Bandizip 的核心，不是文件后缀数量

官方 macOS 页面列出的能力覆盖目录查看、选择解压、代码页、校验、分卷和 Finder 集成 [1]。其中，智能解压针对顶层结构决定输出位置：单文件或单顶层目录直接释放，多顶层内容使用归档同名目录 [2]。因此，单纯给旧解码器外面套一个拖拽窗口，无法还原使用体验。

合理的实现分成三层：

- **解码层**：容器识别、压缩方法、密码、校验和、分卷。必须知道真实解码器版本；扩展名匹配不算解码支持。
- **文件系统层**：目标目录选择、重名策略、元数据、Unicode、链接、失败清理。内容正确但文件名乱码、覆盖原文件或多套目录，仍然是失败的产品行为。
- **交互层**：浏览与搜索、选中解压、预览、进度、暂停、历史和 Finder 服务。每个按钮应对应可用的执行路径。

## 4. 速度分析：正确借鉴并行，而不是把线程全部开满

Bandizip 的官方并行解压说明明确限定 ZIP 的 Store/Deflate，还列出加密、分卷、符号链接及存储介质等不适用条件 [3]。其页面上的提升数据来自特定测试环境，不能直接用作本 App 的性能承诺。

本次新通道解析 ZIP 中央目录，在满足条件时让独立成员并行解码，每个成员拥有自己的 zlib 状态和 CRC-32 校验。读取、解码和写入均使用固定大小缓冲，不读取完整归档进内存。ZIP64、自解压前缀、未知方法、特殊类型或无法安全处理的名字交给通用引擎；这比不完整实现 ZIP 规范后强行接管所有 ZIP 更稳妥。

默认限制两个工作线程，同时仍一次只处理一个归档。原因是磁盘竞争、字典内存、热压力和前台任务响应都可能比逻辑核心数更早成为瓶颈。7-Zip 的 `-mmt` 是能力上限，具体算法未必真的使用相同数量的解码线程。大单文件或 solid archive 的串行依赖不能靠界面线程开关消除。

### 本机可复现的小样本

完整原始结果见 `benchmark-v2.json`，生成与验证脚本为 `scripts/benchmark.py`。

- 64 MiB 合成数据，4 个各 16 MiB 的 Deflate ZIP 成员，固定随机种子。
- 同样的 Utility QoS；串行与默认并行各 3 次，交错运行。
- 串行中位数约 **31.45 ms**；默认并行约 **21.25 ms**，这个样本约 **1.48 倍**。
- 6 次均逐文件通过 SHA-256 对比。
- 命令行进程记录的峰值驻留内存约 **11 MB**；不包含 SwiftUI 界面、系统文件缓存或其他程序，也不能代表 7-Zip 大字典归档内存。
- 这是**热缓存、小规模合成测试**，写入没有逐文件 fsync，不代表冷磁盘持久化时间、长时间热稳定性、所有算法或真实大包。没有与 Bandizip 做同机对照，所以不宣称速度超过 Bandizip。

## 6. 文件保存与安全设计

解码写入目标磁盘内的私有临时目录，完成后发布。单文件或独立目录通过不覆盖的原子重命名落地；“当前位置”涉及多个条目，因此是带普通错误回滚的提交，**不是跨文件的断电事务**。替换时先把原文件移动到临时备份，提交成功后才清理；回滚本身失败时保留备份路径，不删除用户原数据。

链接问题必须同时检查路径和执行时序。原生通道先完成普通文件，再创建内部链接，防止较早创建的符号链接把后续写入导向目录外。路径越界、绝对目标、无效目标或与正常文件冲突时停止。7-Zip 子进程仍依赖解码器自身的路径实现；升级它是兼容性与安全维护的必要工作，不应长期依赖 2017 年的兼容版本。
